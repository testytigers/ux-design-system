# Hard Rules

These are the absolute, non-negotiable rules for Hermes. Each one was created in response to a specific failure mode. Each one has an enforcement check.

If you find yourself wanting to break a rule, **stop, paste the rule to the human, ask permission.** Permission may be granted (rules are not laws), but it must be explicit.

---

## R1 · No nested `var()` arbitrary classes

**Never write** a Tailwind arbitrary value that contains another `var(...)` inside its argument:

```text
🚫  bg-[var(--ux-color-bg-[var(--ux-color-purple-600)])]
🚫  text-[var(--ux-color-text-[var(--ux-color-purple-600)])]
🚫  ring-[var(--ux-color-ring-[var(--ux-color-purple-500)])]
```

The result is invalid CSS — Tailwind does not produce a class for it. The original Hermes shipped 19 components with this exact pattern; none of them rendered. → POSTMORTEM §4.1.

**Allowed forms:**

```text
✅  bg-primary
✅  bg-background
✅  bg-[var(--ux-color-purple-600)]
✅  text-[var(--ux-color-text-on-primary)]
```

The rule is mechanical: count opening `[` characters in any `bg-`, `text-`, `border-`, `ring-`, `fill-`, `stroke-` class. If there's more than one, you broke R1.

**Enforcement:**

```bash
! grep -rE "var\(--ux-color-[a-z]+-\[var" packages/react/src
```

The negation `!` makes the line exit non-zero if grep finds anything. Wire this into CI; it has caught this regression before.

These files **regenerate**. Editing them by hand is wrong:

| File | Generator |
|---|---|
| `docs/components/*.md` (except `overview.md` and `README.md`) | `scripts/generate-component-docs.mjs` |

If you want to change a generated file, edit its **source** and re-run the generator. If the generator output looks wrong, fix the generator.

**Enforcement:** any PR that modifies a file listed above must also modify either the upstream source or the generator. Check the diff.

## R3 · No fictional APIs in documentation or examples

Before you write a code example involving any DS component, **call `get_component_variants`** for that component and use only the variants/sizes returned. Before you mention a prop, **call `get_component`** and verify the prop exists.

**Examples of past offenses** (do not reproduce):

```text
🚫  <Card title="…" description="…">…</Card>     # Card has no such props
🚫  <Button variant="primary">…                  # variant is "default", not "primary"
🚫  <Alert variant="primary">…                   # Alert variants: default/destructive/success/warning/info
🚫  <Modal>…</Modal>                             # there is no Modal — the component is Dialog
🚫  <Badge size="sm">…</Badge>                   # Badge has no size prop
🚫  <Sheet variant="purple">…</Sheet>            # Sheet has `side`, not `variant`
🚫  <Charts type="bar" />                        # Charts is a wrapper, not a self-rendering chart
```

**Process:**

1. Call `get_component_variants(name)`.
2. Look at the response. Note the variant names and size names.
3. Write the example using only those values.
4. Before claiming "done", visually verify your example would compile against the source (call `get_component_source` if you want to be sure).

**Enforcement:** docs are auto-generated by `scripts/generate-component-docs.mjs`, which reads the CVA config directly. Fictional APIs cannot survive a regeneration. If a doc page disagrees with code, the doc loses.

## R4 · No raw colors in component files

In any file under `packages/react/src/components/`:

```text
🚫  bg-white, bg-black
🚫  text-white, text-black
🚫  bg-neutral-100 (or any other raw Tailwind palette class)
🚫  text-neutral-500
🚫  bg-[#ffffff]
🚫  text-[#000]
🚫  style={{ color: "#9333ea" }}
🚫  className="border border-purple-600"
```

Use tokenised equivalents instead. Map:

| Raw | Tokenised |
|---|---|
| `bg-white` | `bg-background` |
| `bg-black` | `bg-foreground` (rare) or `bg-background` for inverted contexts |
| `text-white` | `text-primary-foreground` (on coloured surfaces) or `text-background` |
| `text-black` | `text-foreground` |
| `bg-neutral-100` | `bg-muted` or `bg-secondary` |
| `bg-neutral-200` | `bg-input` |
| `text-neutral-500` | `text-muted-foreground` |
| `text-neutral-600` | `text-secondary-foreground` (or `text-foreground` depending) |
| `border-neutral-200` | `border-border` |
| `bg-purple-100` | `bg-secondary` |
| `text-purple-900` | `text-secondary-foreground` |
| `bg-purple-600` | `bg-primary` |
| `text-purple-600` | `text-primary` |
| `bg-red-600` | `bg-destructive` |
| `ring-purple-500` | `ring-ring` |

**Enforcement:**

```bash
! grep -rnE "(text-\[#|bg-\[#|bg-white|bg-black|text-white|text-black|bg-neutral-|text-neutral-|bg-purple-|text-purple-|ring-purple-)" packages/react/src/components
```

Should return nothing.

## R5 · Every `var(--ux-*)` reference must resolve

If you write `var(--ux-color-foo)` anywhere — CSS, TSX className, Tailwind config — that variable must be defined in `styles/globals.css` (either `:root` or one of its `.dark`/scoped overrides).

**Enforcement (the token-resolves guard):**

```bash
node -e '
const fs = require("node:fs"), { execSync } = require("node:child_process")
const css = fs.readFileSync("styles/globals.css", "utf8")
const def = new Set(
  [...css.matchAll(/^\s*(--ux-[A-Za-z0-9_.\\-]+):/gm)]
    .map(m => m[1].replace(/\\\./g, "."))
)
const grep = execSync(
  "grep -rohE \"var.--ux-[A-Za-z0-9_.\\-]+\" packages styles tailwind.config.ts 2>/dev/null || true"
).toString()
const ref = new Set([...grep.matchAll(/(--ux-[A-Za-z0-9_.-]+)/g)].map(m => m[1]))
const miss = [...ref].filter(v => !def.has(v))
if (miss.length) {
  miss.forEach(v => console.error("MISSING:", v))
  process.exit(1)
}
console.log("OK — all", ref.size, "var refs resolve.")
'
```

Run this **before every commit**. If `Missing: 0`, you pass. If anything is listed, fix it (either define the token or correct the reference).

## R6 · Dark mode is class-based — `.dark`, not `data-theme`

```text
✅  <html class="dark">…
✅  document.documentElement.classList.toggle("dark")
✅  CSS: .dark { … }
✅  Tailwind: darkMode: ["class"]

🚫  <html data-theme="dark">
🚫  [data-theme="dark"] { … }
🚫  document.documentElement.setAttribute("data-theme", "dark")
🚫  darkMode: ["data-theme"]
```

If you find a `data-theme` reference anywhere, it's a regression. Fix it.

**Enforcement:**

```bash
! grep -rnE "data-theme" packages styles tailwind.config.ts docs --include="*.css" --include="*.ts" --include="*.tsx" --include="*.md" | grep -v "corrected\|previous version\|deprecation"
```

(The grep allows the documented "we corrected this from `data-theme`" notes, but blocks active uses.)

## R7 · No framework-agnosticism claims

The README, marketing copy, and docs must not claim:

```text
🚫  "100% portable — no framework lock-in"
🚫  "Works without Tailwind"
🚫  "No runtime dependencies"
🚫  "Pure CSS — drop in anywhere"
```

The system **requires Tailwind v3.4+** to compile. The components have runtime deps on React, Radix UI, lucide-react, etc. Say so plainly.

**Allowed:**

```text
✅  "Built on Tailwind. Tailwind v3.4+ required to compile components."
✅  "Components depend on React 18+ and Radix UI primitives."
✅  "Tokens portable via CSS custom properties. Components require Tailwind."
```

The distinction matters because **consumers who believed the original claims spent half a day debugging unstyled components**.

## R8 · No script-driven component generation

The original `scripts/generate-components.py` produced:

- The 19-file nested `var()` bug (R1).
- The `{components/` and `{packages/` garbage directories (literal-named via unescaped shell brace expansion).
- Phantom kebab-case file references in `tsup.config.ts` that never matched real files.

**The script is deprecated and stubbed.** Do not revive it. If you want batch generation, write a TypeScript codemod with snapshot tests on its output, and treat each batch as a normal PR (reviewable, revertable).

**Enforcement:** the stubbed `scripts/generate-components.py` raises on import. Reviving its functionality requires explicit human approval and snapshot tests.

## R9 · Major version bumps require sign-off

Especially for `lucide-react` (currently pinned to `1.14.0`, should move to a current `0.x`), but the rule generalises.

A major version bump is **not** "update the deps". It is a tracked PR with:

1. A migration note in CHANGELOG.
2. A test that every icon import in the components still resolves (icon names change between lucide majors).
3. Build green on both packages.
4. Smoke import of every barrel export from a fresh `npm pack`.

If you're not sure whether a bump is safe, **stop and ask**.

**Enforcement:** manual code review. There is no automatic gate. The reviewer's job is to ask "did you test every consumer?"

## R10 · Validation before commit

Before any commit that touches `packages/` or `styles/`, run [PLAYBOOK-validation.md](./PLAYBOOK-validation.md) §3 in full. Specifically:

```bash
( cd packages/tokens && node scripts/build.mjs ) 2>&1 | tail -3
( cd packages/react  && node scripts/build.mjs ) 2>&1 | tail -3
# R5 guard
node scripts/check-tokens.mjs   # or the inline one-liner above
# R1 guard
! grep -rE "var\(--ux-color-[a-z]+-\[var" packages/react/src
# R4 guard
! grep -rnE "(text-\[#|bg-\[#|bg-white|bg-black|text-white|text-black|bg-neutral-|text-neutral-|bg-purple-)" packages/react/src/components
# Export count
node --input-type=module -e "import('./packages/react/dist/index.js').then(m => process.exit(Object.keys(m).length >= 193 ? 0 : 1))"
```

If any of these fail: do not commit.

If you wrote `pnpm commit` without running these: **revert your commit, run the checks, and try again**.

## R11 · CHANGELOG is part of the change

Every user-visible change (token added/removed, component variant added/removed, behavior change, dep bump, doc rewrite) gets a CHANGELOG entry **in the same commit**.

```markdown
## [Unreleased]

### Tokens
- Added --ux-color-card-emphasis (light: neutral-50, dark: neutral-900) for emphasised cards.

### Components
- Button: new `size="xl"` (h-12 px-10 text-lg).
- Form: FormControl now forwards aria-invalid from useFormField.

### Fixes
- Carousel: the `orientation` prop now actually applies on CarouselPrevious/Next (was undefined).
```

If you forgot the CHANGELOG, the commit is incomplete.

---

## R12 · Hermes-self-honesty

If you make a mistake:

1. **Stop.** Do not "patch over" — revert.
2. **Tell the user.** Don't hide it.
3. **Add an entry to POSTMORTEM.md** describing what happened and how to prevent it next time.
4. **Update the hard rules** if a new failure mode appeared.

The original Hermes shipped a non-functional DS by hiding failures behind plausible-looking docs and self-reported scores. The new Hermes does not hide. Owning a mistake costs much less than letting it ship.
